# Rust TOTP CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an offline Rust TOTP CLI with native credential storage on Windows, macOS and Linux.

**Architecture:** A single library/binary package separates enrollment validation, QR decoding, credential access, transactional metadata updates and CLI presentation. The production vault is native; ordinary tests inject in-memory credentials. The new repository and data namespace remain independent of the Python implementation.

**Tech Stack:** Rust, clap, totp-rs, rqrr, image (PNG/JPEG only), keyring, serde_json, tempfile, fs2, uuid, Unicode normalization/case folding.

## Global Constraints

- Independent repository `totp-cli-rs`; namespace `local-totp-cli-rs`; binary `totp`.
- No third-party C/C++ compilation, OpenSSL or libdbus development dependency; platform SDKs/linkers and OS credential services remain required.
- Directly store each account's shared secret in the OS vault; no application master key, master password or plaintext fallback.
- URI at most 8192 UTF-8 bytes and 16 query fields; PNG/JPEG at most 20 MiB and 4000 万像素; index at most 1 MiB.
- SHA1/SHA256/SHA512, 6/8 digits, period 1–86400 seconds; aliases 1–64 Unicode characters, NFC normalization and full case folding.
- Metadata format `local-totp-cli-rs`, version 1, top-level fields `format`, `version`, `accounts`; records contain `id`, `alias`, `account`, `issuer`, `algorithm`, `digits`, `period` only.
- Credential service `local-totp-cli-rs/<UUID>`, username `totp-secret`; Windows local-machine persistence.
- 5-second lock timeout; Unix directory/file modes 0700/0600; failed imports compensate only their newly allocated credentials.
- Exit codes 0/1/2/130; no secret, complete URI or raw backend error in user-facing errors or debug output.
- Work in the already-created separate repository. Do not create branches/worktrees, commit, push or publish.
- Use red/green tests for implementation and report only platforms actually tested.

## Shared Interfaces

```rust
pub type Result<T> = std::result::Result<T, AppError>;
pub struct AppError(String);
impl AppError { pub fn new(message: impl Into<String>) -> Self; }

pub enum Algorithm { Sha1, Sha256, Sha512 }
pub struct Enrollment {
    secret: zeroize::Zeroizing<String>,
    pub account: String,
    pub issuer: String,
    pub algorithm: Algorithm,
    pub digits: usize,
    pub period: u64,
}
impl Enrollment {
    pub fn new(secret: &str, account: &str, issuer: &str,
               algorithm: Algorithm, digits: usize, period: u64) -> Result<Self>;
    pub fn secret(&self) -> &str;
    pub fn code_at(&self, timestamp: f64) -> Result<(String, u64)>;
}
pub fn parse_enrollment(uri: &str) -> Result<Enrollment>;
pub fn read_enrollment(path: &std::path::Path) -> Result<Enrollment>;

pub trait Vault: Send + Sync {
    fn get(&self, id: &str) -> Result<Option<zeroize::Zeroizing<String>>>;
    fn put(&self, id: &str, secret: &str) -> Result<()>;
    fn delete(&self, id: &str) -> Result<()>;
}
pub struct NativeVault;
impl NativeVault { pub fn new() -> Self; pub fn label() -> &'static str; }

pub struct Store<V: Vault> { directory: std::path::PathBuf, vault: V }
impl<V: Vault> Store<V> {
    pub fn new(directory: std::path::PathBuf, vault: V) -> Self;
    pub fn list(&self) -> Result<Vec<Account>>;
    pub fn add(&self, alias: &str, enrollment: &Enrollment) -> Result<()>;
    pub fn get(&self, alias: &str) -> Result<Enrollment>;
    pub fn remove(&self, alias: &str) -> Result<()>;
}
```

Interfaces are shown as signatures, not compilable implementations. Final concrete implementation is in source files, avoiding a duplicate source tree in documentation.
