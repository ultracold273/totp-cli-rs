# TOTP CLI Rust 迁移设计

日期：2026-09-25。状态：已实现并完成本机与交叉检查；其他平台原生验证待 CI 执行。

## 1. 已确认的方向

- 使用独立的本地 Git 仓库 `totp-cli-rs`，不修改 Python 仓库，不自动创建远程仓库。
- 不要求兼容 Python 版本的数据格式、凭据标识或内部实现。
- 优先采用 Rust 原生依赖，不编译或链接第三方 C++ 二维码库。
- 保留系统凭据库：直接保存每个账户的 TOTP 共享密钥，不引入应用主密码或应用主密钥。
- 下述命令范围、数据格式和实施细节为用户确认的实施方案。

## 2. 方案选择与边界

采用“系统凭据库保存密钥，普通文件保存元数据”的方案，与参考实现的安全边界一致。
不采用“应用主密钥保存在系统凭据库，再由应用加密一个密钥文件”的双层方案：
本次没有必须由应用管理密文文件的需求，因此不增加该层密钥管理。
也不采用“用户输入主密码解锁独立加密文件”的方案，以免引入新的解锁、备份和恢复流程。

系统凭据库的底层保护由对应操作系统或服务实现提供，Rust 应用只调用明确选定的凭据后端。
这不意味着可以抵御所有同一登录用户下的恶意软件，也不意味着密钥从不进入进程内存。
生成验证码时必须取出共享密钥；实现应尽量减少其副本和存活时间，不承诺无法验证的彻底内存擦除。

不支持明文密钥文件回退；凭据库不可用、被锁定或拒绝访问时，依赖密钥的命令明确失败。
不做自动同步、密钥导出、Python 数据迁移、HOTP、推送认证、Passkey 或批量迁移二维码支持。

## 3. 用户接口

可执行文件名为 `totp`，保留下列使用方式；通过路径区分 Python 与 Rust 版本。

| 命令 | 行为 |
| --- | --- |
| `totp add NAME --qr PATH` | 从本地 PNG/JPEG 导入一个 TOTP 账户，同名账户不覆盖 |
| `totp list` | 展示非密钥元数据，不访问凭据库 |
| `totp list --json` | 输出结构化元数据，不包含密钥 |
| `totp code NAME` | 标准输出仅包含验证码及换行 |
| `totp code NAME --watch` | 在交互终端刷新验证码及倒计时，Ctrl+C 退出 |
| `totp remove NAME` | 删除本地凭据及元数据，不更改网站的双因素设置 |
| `totp doctor` | 展示平台、所选后端、索引路径和账户数量，不写入测试凭据 |
| `totp --data-dir PATH COMMAND` | 更改元数据目录，不更改密钥存储策略 |

保留 `--help`、`--version`。错误写入标准错误；成功退出码为 0，操作错误为 1，参数错误为 2，
用户中断为 130。参数错误不回显可能被误粘贴为参数的密钥或完整注册 URI。
`--watch` 在非交互终端中拒绝运行。`doctor` 不将“选择了一个后端”表述为“凭据读写测试已通过”。

别名允许 1–64 个 Unicode 字符，以字母或数字开头，其余为字母、数字、点、下划线或连字符。
先做 NFC 规范化，再用 Unicode 完整大小写折叠比较；不将别名用作文件名或凭据 ID。

## 4. 模块边界与依赖策略

使用一个 Cargo 包，包含可测试的库和薄 CLI 入口，不预先拆分多包工作区。

| 模块 | 职责 | 与其他模块的接口 |
| --- | --- | --- |
| `cli` | 参数解析、输出、退出码及 watch 循环 | 调用账户操作，不实现加密或索引写入 |
| `enrollment` | 严格解析注册 URI，校验密钥及算法参数，计算 TOTP | 返回有效注册对象；不访问文件或系统凭据库 |
| `qr` | 有界读取图片、处理方向和透明度、检测二维码 | 返回经过校验的注册对象，不持久化图片或载荷 |
| `vault` | 系统凭据的读取、写入和删除 | 小型可注入接口；测试用内存实现 |
| `store` | 元数据校验、账户查找、锁、原子写入和跨存储补偿 | 调用 vault 接口，不负责验证码计算 |
| `error` | 安全的用户错误分类 | 默认不暴露底层异常内容或敏感对象 |

计划使用 `clap`、`totp-rs`、`rqrr`、`image`、`keyring`、`serde`/`serde_json`，
以及满足文件锁、临时文件和平台目录需求的最小依赖集合。
确切版本和最低 Rust 版本在实现阶段依据实际解析和构建结果确定，提交生成的 `Cargo.lock`。
当前本机 Rust 为 1.89.0，先验证依赖能否支持它，而不是未经构建便宣称兼容。

- `rqrr` 用于二维码检测和解码，不使用 zxing-cpp、OpenCV 或 ZBar。
- `image` 禁用默认 features，仅启用 PNG/JPEG；不因图片库默认配置引入其他编解码器。
- `totp-rs` 仅承担已验证参数下的验证码计算；关闭不需要的二维码和 URL 功能。
- macOS/Linux 使用 `keyring` 显式选择后端，生产构建不能意外落到 mock 后端。
- Windows 通过 `windows-sys` 调用原生 Credential Manager，显式使用本机持久化而非库默认的 enterprise 持久化。
- Linux 采用异步 Secret Service 后端、一个明确选择的运行时和 Rust 加密 feature，
  避免同步后端引入 `libdbus` 开发库；不使用 OpenSSL 后端。
- 不将密钥字段序列化到元数据，不为包含密钥的类型提供泄漏内容的调试输出。

“无第三方 C++ 依赖”不等于“没有任何平台接口”：Windows Credential Manager、macOS Keychain
和 Linux Secret Service 仍然需要对应的系统设施。标准 Rust 构建所需的链接器或平台 SDK 不在排除范围内。

## 5. 注册与图片处理

只接受 `otpauth://totp/` 注册信息；默认 SHA1、6 位、30 秒，支持 SHA256/SHA512、8 位及
1–86400 秒的整数周期。拒绝未知或重复参数、非法 UTF-8/百分号编码、控制字符、非规范 Base32、
发行方冲突及不支持的算法；不得在错误中回显注册信息。
URI 限制为最多 8192 个 UTF-8 字节、16 个查询参数。对 Base32 做解码和重新编码校验，
接受合法的大小写及填充形式并统一规范化；不静默修复非法尾部位。

图片最多 20 MiB、4000 万像素。先限制文件读取量，再在解码前根据图片头限制尺寸和解码分配。
处理 EXIF 方向，透明区域合成到白底，转换灰度后进行普通及反色检测。
实施时复现了 `rqrr 0.11` 在允许范围内大图上的 `i32` 求交溢出，因此检测前仅做一次等比缩图，
最长边不超过 1024。实际角点坐标上界为 1023，使已复现求交分子的界限 `2 * 1023^3` 小于 `i32::MAX`。
这不是对第三方解码器所有畸形输入的无 panic 保证。大画布中的小码可能在缩图后无法识别，
用户应裁剪并保留留白；不引入自动裁剪、多尺度重试或无界扫描。
旋转识别以测试验证，不假设更换解码器后自动具备与 Python 版完全相同的鲁棒性。
按完整解码载荷去重；先按 `otpauth://totp/` 前缀统计已解码候选，再解析唯一候选。
多个不同候选一律拒绝，包括其中一个参数无效的情况；无关二维码不遮蔽有效 TOTP 码。
保留原始截图，不上传、修改或自动备份它；截图本身仍是包含共享密钥的敏感文件。

## 6. 数据布局与凭据隔离

生产构建的新数据命名空间固定为 `local-totp-cli-rs`。默认目录为：

- Windows：`%LOCALAPPDATA%\local-totp-cli-rs`。
- macOS：`~/Library/Application Support/local-totp-cli-rs`。
- Linux：`${XDG_DATA_HOME:-~/.local/share}/local-totp-cli-rs`。

目录中只有版本化的 `accounts.json`、锁文件及短暂存在的元数据临时文件。
索引最多 1 MiB。顶层字段为 `format`、`version`、`accounts`；
`format` 固定为 `local-totp-cli-rs`，`version` 固定为 1。
账户字段为 `id`、`alias`、`account`、`issuer`、`algorithm`、`digits`、`period`，没有 `secret`。
读取时拒绝重复 JSON 字段、未知字段、不支持的版本、重复 ID、重复规范化别名和非法参数。
明确的格式标识确保误选 Python 数据目录时拒绝其索引而不是自动覆盖。

每个账户使用随机 UUID；凭据 service 为 `local-totp-cli-rs/<UUID>`，用户名为 `totp-secret`。
Windows 设置为本机持久化，不开启漫游；macOS 使用 Keychain；Linux 使用持久化 Secret Service，
不将内核会话 keyring 当作唯一存储，不允许明文回退。不会枚举或更改 Python 版本的凭据。
原样写入凭据接口的是 TOTP 共享密钥，不是用于加密其他文件的应用主密钥。

原生测试专用编译期 feature `native-test` 将 service 前缀和默认目录名改为
`local-totp-cli-rs-native-test`，版本输出带 `(native-test namespace)` 标记；仍使用真实系统后端，
不提供运行时后端/命名空间切换。测试使用临时元数据目录与随机凭据 ID。
原生 CLI 测试先验证该标记，拒绝生产二进制（包括通过 `TOTP_TEST_BINARY` 指定的二进制）。
发行构建不启用该 feature，CI 在测试完成后重新构建默认 release。

## 7. 一致性和故障处理

所有索引读改写使用跨进程锁，等待上限为 5 秒。元数据通过同目录临时文件、刷新和原子替换更新，
并验证 Windows 下的关闭与替换顺序。Unix 上新建目录权限为 0700、文件为 0600；
Windows 使用当前用户数据目录的访问控制，不将 Unix 模式位视为 Windows 安全保证。

- **导入**：检查重复账户，生成新 ID，写入凭据，再提交索引；失败时尝试删除新建凭据。
  回滚失败单独报告，并提供非敏感凭据 ID 供清理；不删除已有账户凭据。
- **删除**：删除凭据后更新索引；若索引提交失败，允许重试完成清理。
  已不存在的凭据视为可恢复状态。
- **读取**：索引损坏时拒绝覆盖；凭据缺失时提示重新导入，不返回错误密钥或空验证码。
- **崩溃边界**：系统凭据库和 JSON 不是同一个事务存储。普通错误使用补偿操作处理，
  但强制终止或断电仍可能留下孤立凭据或缺少凭据的索引项；不承诺跨存储崩溃原子性。
- **输出**：不将共享密钥、完整 URI、图片载荷或可能包含这些内容的底层错误写入日志和错误消息。

## 8. 验收与交付

普通测试只使用公开测试密钥和内存凭据库，不访问真实账户。

1. RFC 6238 的 SHA1/SHA256/SHA512 全部 18 个测试向量、前导零、时间边界、自定义周期和非法时钟。
2. URI 严格解析、Unicode 别名和参数错误脱敏。
3. 实际生成的 PNG/JPEG 二维码、Unicode 路径、旋转、反色、透明度、多二维码和图片资源限制。
4. 元数据与密钥分离、重复账户、损坏索引、锁超时、跨进程并发更新、写入故障和补偿失败。
5. CLI 输出和退出码；`list` 不访问 vault；watch 的刷新、非终端拒绝和中断行为。
6. 显式启用的原生凭据测试只创建独立测试命名空间下的临时凭据并清理，不打印其密钥。
7. Windows、macOS、Linux CI 执行格式、lint、测试和 release 构建；无 Secret Service 的 Linux
   环境可运行内存后端测试，但不能将其视为原生凭据验证。
8. 用 `cargo tree -e features --target <target>` 检查三个目标的依赖图，并结合实际构建检查
   C/C++ 编译、OpenSSL、libdbus 及非预期图片编解码器；仅存在 Rust FFI 类型并不等于编译 C++。

交付内容为独立仓库中的源代码、锁文件、测试、三平台 CI 和安装/安全边界说明。
只报告真正执行过的构建和测试；本机验证不代替其他平台验证。
本次不发布包、不签名、不推送远程，也不创建 Git 提交，除非用户另行要求。
